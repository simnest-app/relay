# SimNest 自建中继部署包

把它跑在你自己的云主机或家里的 NAS 上，你的网关和 iPhone 之间连不通时，通话就经这台机器转发，而不经官方中继。

- 中继只转发加密后的声音，听不到也改不了通话内容：通话两端之间另有端到端加密。
- 自建中继不连接 SimNest 的服务。它的地址和密钥只在你的网关上，服务端不知道有这台中继。
- 中继能看到的是：通话两端的公网地址、什么时候通话、通了多久。所以它应该放在你自己管的机器上。

**现状**：这个部署包的程序和安全配置都有自动测试，网关也已经能添加和使用自建中继；但“在一台真实的云主机或 NAS 上部署，再让通话走它”这一整条路还没有实地验证过。先试用的话，请留意设置页面上的自检结果，遇到问题欢迎提 Issue。

配合使用的网关：[simnest-app/gateway](https://github.com/simnest-app/gateway)。

许可：GPL-3.0（见 `LICENSE`）。coturn 是它自己项目的官方镜像，BSD-3 许可（见 `NOTICE`）。

## 里面有什么

| 部分 | 说明 |
| --- | --- |
| coturn | TURN 中继，官方镜像 `coturn/coturn:4.18.0`，按镜像摘要固定，不会自己变成别的版本 |
| 小助手 `helper/` | 我们写的 Go 小程序：第一次运行生成密钥，写出 coturn 的安全配置，在局域网网页上显示给网关扫的二维码，并自检。默认用已发布的镜像 `simnest/relay-helper`（x86 和 ARM 都有，按镜像摘要固定），也可以用这里的源码自己构建 |
| `helper/turnserver.conf.tmpl` | 安全配置模板：只认临时凭据、限额、禁止转发到内网和保留地址（含 IPv4 写成 IPv6 的各种写法）、不替别人连 TCP |

## 需要什么

- 一台有公网地址的机器。云主机可以直接用；家里的机器要在路由器上做端口映射，而且宽带得有公网地址。运营商级 NAT（公网地址以 100.64 到 100.127 开头，或者路由器上看到的地址和外面查到的不一样）后面的机器当不了中继。
- Docker 和 Docker Compose。
- 防火墙和路由器放行：3478 的 UDP 和 TCP，49160 到 49359 的 UDP。
- 每通电话大约占 100 kbps 上行带宽。

## 怎么部署

```bash
cp .env.example .env
```

编辑 `.env`，把 `EXTERNAL_IP` 填成这台机器的公网地址，然后：

```bash
docker compose up -d
```

```bash
docker compose logs helper
```

日志里有一行设置页面的地址（带一串钥匙）。在同一个局域网里用浏览器打开它，页面上有二维码和自检结果。云主机没有局域网时，用 SSH 把端口转到自己电脑上再打开（`ssh -L 8787:127.0.0.1:8787 你的主机`，然后把地址里的主机换成 `127.0.0.1`）。

Docker 不支持共用主机网络时（Docker Desktop、部分 NAS），改用：

```bash
docker compose -f docker-compose.yml -f docker-compose.bridge.yml up -d
```

这种方式只有 IPv4；网关和这台机器在同一个局域网时，要在 `.env` 里填 `LAN_IP`。

### 拉不到镜像时

小助手的镜像放在 Docker Hub 上。这台机器连不上 Docker Hub，或者你想运行自己改过的代码时，改为用 `helper/` 里的源码在本机构建：

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

要同时用上面的 `docker-compose.bridge.yml`，就把三个文件都写上。本机构建需要能下载 Go 的构建镜像；coturn 的官方镜像也在 Docker Hub 上，拉不到的话要先给 Docker 配镜像加速。

## 在网关上添加

在网关上打开“网络与中继”里的“自建中继”，把设置页面上的文字粘贴进去（页面上点“显示可以粘贴的文字”）。网关里现在没有扫码：可以用手机系统自带的扫码读出二维码里的文字，复制后粘贴，内容是一样的。网关会立刻实测一次：能不能连上、能不能申请到中继、往返多少毫秒。

二维码里有中继的密钥，不要截图发给别人。密钥泄露了就删掉数据卷里的 `secret`（或者整个数据卷）重新启动，再在网关上重新添加。

## 更新

换成新版本的部署包，或者改了 `.env` 之后：

```bash
docker compose pull
```

```bash
docker compose up -d --force-recreate
```

用本机构建的话，改成 `docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build --force-recreate`。

**从端口到 49200 的旧版本更新过来的，先放行新端口再更新。** 默认的中继端口从 49160–49200 扩到了 49160–49359，每台设备的名额从 6 个加到 24 个、总数从 20 个加到 160 个：通话中手机换网络（Wi-Fi 换手机流量）时，旧网络上占的名额要十分钟才还，原来的 6 个不够用，换网后会连不上。更新前在防火墙、安全组和路由器映射上把 UDP 放行到 49359；没放行就更新，中继会把通话分到没放开的端口上，大部分通话经中继不通。不想多开端口的，在 `.env` 里写上 `MAX_PORT=49200` 和 `TOTAL_QUOTA=40`，保持原来的范围，名额仍比以前宽。

`--force-recreate` 让 coturn 也重新启动，用上小助手新写的配置；不加的话 coturn 还在用旧配置。重启的几秒里，正在经这台中继的通话会断一下。密钥和设置都在数据卷里，更新后不用在网关上重新添加。

## 这一版没有的

- TLS（`turns:`）：声音本来就端到端加密，这一版只有 UDP 和 TCP。
- 自动测上行带宽、自动提示有新版本。
- 把中继共享给其他用户：没有开放。

## 发现安全问题

请不要把细节公开发出来。在 GitHub 仓库开一个 Issue，只写“有安全问题想私下说”，不写内容，维护者会联系你。
